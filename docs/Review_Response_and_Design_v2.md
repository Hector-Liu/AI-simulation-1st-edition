## 0. 一页摘要

**总体判断：** 审阅意见质量很高。P1 的四条都成立，我全部采纳。但有几处论证或做法我认为需要修正，才能真正达到目的：

1. **P2-2 的 voter 零模型漏了"噪声"。** 纯 voter 是吸收过程，而 LLM 在温度 > 0 下每轮都会按先验"随机重新选"，所以零模型要加创新项 ε。A(k) 这个比值在 p0 很小的标签上极不稳定，我建议改用单参数的**先验敏感指数 γ**：P(获胜 = k) ∝ p0(k)^γ。
2. **P2-9 的 fitted_logit 不应该用同一批运行的前半段来拟合。** 那样有循环论证。应当用反事实探针（外生操纵的数据）来拟合，并在留出的标签集上先检验个体层面的拟合度，再去解释宏观预测的成败。
3. **P2-4 的"噪声下限"应该由"锁定探针"测量，而不是 Study 0。** Study 0 测的是无条件先验，不是收敛之后的稳定性。
4. **P3-1 的成本论证有误。** 星形每轮只有 2 次调用，一次运行只要约 $0.18，是最便宜的一行。降级它的理由是信息量低，不是成本。而且按叶节点 t_pc 放大轮数也很便宜（约 $0.7 / 次）。
5. **P2-6 的自我报告是弱证据**，问题本身还可能诱导"协调"的理解。我补了一个**行为层面**的操纵检查：无奖励臂中，反事实探针的剂量–反应斜率。
6. **回复第 2 条：** L1–L3 目前只有冒烟测试和 mock 数据，没有正式数据。所以应该整体重新生成 10 组标签集，而不是走"保留 + 协变量"的路线。

**我额外发现的问题：**

- P1-2 的"匹配先验"有一个漏洞：own_only 格去掉了交互段落的第二句，所以它的首轮提示词与无记忆格**不同**，需要单独的先验格。
- 每个标签集的先验样本量不够，需要单独补样。
- own_prev 安慰剂检验要成立，前提是隐藏智能体编号：编号本身会造成个体差异。
- 这些都已写进 SPEC v2。

**修订后的设计核心：**

- **2 × 3 核心设计：** 奖励 × {无记忆, 只看自己, 自己 + 伙伴}，全部使用 choices_only。
- **两个主假设：** H2a（无奖励下，"自己 + 伙伴"的最终熵低于"只看自己"）和 H4（γ 低于噪声 voter 零模型）。H4 是否进主假设族，取决于检验力模拟。
- **三种探针：** 反事实、锁定、操纵检查。
- **fitted_logit** 做微观 → 宏观预测。
- **10 组标签集**，全部使用提示词匹配的先验。

**预算（Haiku 4.5，300 轮）：** 全部约 **$710**。其中核心 2×3 约 $259，探针和校准约 $5。预实验很可能把轮数减半，核心部分会降到约 $125。

## 2. 修订后的研究设计

### 2.1 构念与"涌现"的判据

- **有奖励臂：** 命名博弈意义上的惯例（最小形式的 Lewis 惯例，没有共同知识）。
- **无奖励臂：** 共享行为规律。只有当探针显示存在条件从众（伙伴暴露提高选择概率，且超出自我坚持），才讨论"隐性协调偏好"。
- **涌现的主张：**
  - (a) 获胜的规律不由提示词匹配的先验决定；
  - (b) 在不同种子之间存在路径依赖；
  - (c) 分两种情况报告：能由个体选择函数预测 → **弱涌现（有微观解释）**；不能预测且个体模型合格 → **高阶历史效应**。

### 2.2 假设

| 假设 | 内容 | 族 |
|---|---|---|
| **H2a** | 无奖励：entropy_final(自己 + 伙伴) < entropy_final(只看自己)，H = 5 | 主要 |
| **H4** | γ̂ 低于带噪声 voter 零模型的 γ 分布带（获胜标签不只是在重放先验） | 主要（前提是检验力 ≥ 0.8） |
| H1a | 有奖励：entropy_final(自己 + 伙伴) < entropy_final(只看自己) | 次要 |
| H2b / H1b | 有记忆格低于同一臂的无记忆格 | 次要 |
| H3 | 反事实探针：伙伴记录中 k 的次数增加，选 k 的概率上升（因果的机制证据） | 次要 |
| H6 | fitted_logit 能预测宏观结果（entropy_final、T_consensus、γ、碎片化） | 次要 |
| H5 | 社区拓扑：p_within 越高，碎片化越多 | 探索性 |
| E1–E4 | 得分反馈、记忆长度 H、温度、少数派临界点 | 探索性 |

### 2.3 设计矩阵

**核心 2 × 3：** 随机配对，N = 24，H = 5，choices_only，隐藏编号，模板 v2。10 个标签集 × 3 个种子 = 30 次运行 / 格，且同一组（标签集, 种子）用于所有格。

| | 无记忆 | 只看自己 | 自己 + 伙伴 |
|---|---|---|---|
| **无奖励** | B0 先验基线 → p0_B | B1 | **B2 关键格** |
| **有奖励** | A0 焦点对照 → p0_A | A1 | **A2** |

**辅助格与探索性格：**

| 块 | 内容 | 用途 |
|---|---|---|
| 先验格 B0′ / A0′ | 无记忆，但使用 own_only 的交互段落 | 给 B1 / A1 提供匹配先验 |
| Study 0 | 孤立模板 | 标签闸门；测量"语境让先验变尖多少" |
| S1 / S2 | 有奖励 + numeric_score（S2 即原 Study A 格） | E1 得分反馈；E2 在 S2 上取 H = 1 / 10 |
| 社区 | p_within ∈ {0.8, 0.9, 0.99} | H5 |
| 星形 | 按 t_pc 放大，约 1 150 轮 | 探索性 |
| 少数派 | N = 48，2–30 % 共 7 个水平 | E4 |
| 第二家族 | 开源模型复制核心 6 格和探针 | 推广性 |

### 2.4 三种探针（无状态调用，不进入模拟动态）

| 探针 | 做法 | 得到什么 | 调用次数（Haiku） |
|---|---|---|---|
| **P-CF 反事实** | 析因设计：伙伴记录中焦点标签的次数 0–5，自己的记录固定为其他标签；两臂各做一遍 | H3 的因果剂量–反应；fitted_logit 的参数 θ；行为层面的操纵检查 | 约 6 000（约 $1.2） |
| **P-LOCK 锁定** | 记忆全部为"你选 k、对方也选 k" | 噪声下限、共识阈值校准、零模型的 ε | 约 4 000 |
| **P-MC 操纵检查** | 把最后的指令换成"用一句话描述这个任务要你做什么"，盲化后双人编码 | 辅助证据：任务是否被理解为"要与对方一致" | 约 300 |

### 2.5 零模型与分析

- **零模型：**
  - 所有规则策略都加创新项 ε，由 P-LOCK 校准；
  - 每格各跑 10 000 个种子（向量化实现），使用匹配先验，并按 Dirichlet 分布传递先验的估计误差。
- **主要结局：** `entropy_final`。用混合模型分析：`entropy_final ~ memory × reward + (1 | 标签集 / 种子对)`，用 beta 回归或 logit 变换后的线性模型。结果不显著时做 TOST。
- **H4：** γ 的多项分布极大似然估计；与 voter、majority_H、fitted_logit 的 γ 分布带比较，分三档解读；辅以获胜标签的先验排名、P(获胜 = argmax p0)，A(k) 只做描述。
- **H6：** fitted_logit 放进同一个调度器跑 1 000 个种子，看 LLM 的宏观结果是否落在 90 % 预测带内。
- **检验力模拟：** 在预注册之前完成，用来决定每格运行数，以及 H4 是否进入主假设族。

### 2.6 从预实验到预注册

1. 生成标签集 → 人工审查 → 冻结 → 每组跑 Study 0。
2. 预实验：核心 6 格 × 4 组（标签集, 种子）× 2 个温度。
3. 从预实验数据推导匹配先验，并与孤立先验比较。
4. 探针：P-LOCK → P-CF → P-MC（人工编码）。
5. 拟合 fitted_logit（先做留出检验）→ 零模型 → 检验力模拟 → 确定轮数、每格运行数、SESOI、主假设族。
6. 导出预注册包 → 预注册。
7. 正式运行（各格随机交错）→ 分析 → 对照涌现判据清单。

**修订后的涌现判据清单：**

1. 最终熵：自己 + 伙伴 < 只看自己，且低于 prior_sample 零模型；
2. γ̂ 低于 voter 零模型的分布带；
3. 探针剂量–反应为正（社会影响**机制**存在：必要，但不充分）；
4. 报告 H6 属于"可解释"还是"高阶"；
5. 报告碎片化比例；
6. 泄漏审计 100 % 通过，每个纳入的格的无效率都低于阈值。

## 3. 软件设计思路

### 3.1 原则（沿用 v1，不变）

- 唯一的提示词构造函数和唯一的记忆写入函数；
- 禁用词检查一旦命中就停止；
- 逐字记录提示词；
- 按用途和轮次派生随机数；
- 智能体读不到分析数据。

**新增的原则：**

- **探针也必须通过同一个提示词构造函数生成：** 用合成的记忆记录来构造，不在日志文本上直接改字符串。
- **按阶段隔离：** pilot / confirmatory / probe / null 的数据分开存放。正式运行不能使用由正式数据推导出的先验或 θ。
- **先验和参数都有出处：** p0、θ、ε 都以带哈希的文件保存，配置文件只引用它们，manifest 记录解析后的值。

## 4. 用户使用流程（v2 目标）

| 步骤 | 你的操作 | 系统自动完成 |
|---|---|---|
| 1 标签集 | Study plan → 生成候选标签集 → 下载审查表 → 逐个标记 ok / replace → 上传 → Freeze | 多语言与近似词过滤；替换标签；写入哈希和冻结日期；冻结后禁止再生成 |
| 2 Study 0 | 点"Run Study 0 (all sets)"，确认费用 | 每组 400 次调用；给出闸门结果；标记的组重新生成一次 |
| 3 预实验 | 点"Core 2×3 pilot"，确认费用 | 6 格 × 4 组 × 2 个温度，随机交错执行；实时监控 |
| 4 先验 | 点"Derive matched priors" | 校验首轮提示词逐字相同；计算 p0_A、p0_B、p0_B1、p0_A1 并存档；与孤立先验对比 |
| 5 探针 | Probes 页依次运行 P-LOCK、P-CF、P-MC；下载盲化编码表，完成人工编码后上传 | 计算 ε、噪声下限、剂量–反应曲线、κ |
| 6 拟合与零模型 | 点"Fit fitted_logit"，然后点"Nulls + power" | 留出检验；每格 10 000 个种子的零模型；检验力模拟，并**给出建议**（轮数、每格运行数、SESOI、H4 是否进主族），由你决定是否接受 |
| 7 预注册 | 点"Export prereg bundle"，去 OSF 提交 | 打包所有冻结的材料及其哈希 |
| 8 正式运行 | Study plan 中按块启动 | 随机交错执行；快照锁定；阶段隔离；可以续跑 |
| 9 分析 | Results → 下载各块的数据 → 在 R / Python 中运行分析脚本 → 对照判据清单 | 运行层面汇总表、选择模型数据、探针数据、H4 / H6 面板 |

现在的"Setup → Monitor → Results"单次运行流程保留，适合临时测试。
