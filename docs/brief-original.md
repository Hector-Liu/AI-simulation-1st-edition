# Implementation brief: emergence experiments in an LLM agent simulator

Purpose: support two experiments on collective convention formation.

1. Rewarded local naming game: global convention from local match payoffs.
2. No task-contingent reward: spontaneous convergence from local interaction history alone.

This document is an engineering specification. It is not a claim that either outcome is emergence until the measurement tests pass.

## Non-negotiable invariants

These must be true in the default experimental runtime. Violations invalidate the study.

1. An agent may store text only from interactions in which that agent participated.
2. An agent must not receive other pairs' transcripts, a shared whiteboard, a global chat log, or population frequencies.
3. The current partner's current-turn choice may be shown only after both choices are committed, and only to the two participants.
4. No prompt may contain the words or implications: consensus, agree, coordinate, cooperate, align, successful interaction, common language, maximize collective performance, or "the group should converge."
5. Reward, success/failure labels, and numeric scores are condition flags. They must be absent from prompts unless `reward_mode=local_match` and `feedback_mode` explicitly allows them.
6. The exact prompt sent to each model call must be logged. A leakage test must fail the run if forbidden strings appear.
7. Label display order must be randomized per prompt. Labels must be nonce strings regenerated or reshuffled per run.
8. Agents must not see future partners, the full population roster's choices, or who is "winning."

## Architecture

Separate four layers. Do not let the measurement layer write back into agent context.

### 1. ExperimentConfig

Immutable per run. Serialize to JSON and hash it.

Required fields:

- `experiment_id`: `rewarded_naming` | `no_reward_convergence`
- `run_id`, `seed`
- `n_agents`: default 24; allow 12, 24, 48
- `n_rounds`: default 300
- `pairing`: `random_dyad` | `star` | `community`
- `memory_mode`: `none` | `own_interactions_only`
- `memory_horizon_H`: integer, default 5; also test 0, 1, 3, 10
- `reward_mode`: `none` | `local_match`
- `feedback_mode`: `choices_only` | `success_failure_label` | `numeric_score`
- `payoff`: `{match: 1, mismatch: 0}` or `{match: 100, mismatch: -50}` only if rewarded
- `label_pool_size`: 8 or 10
- `n_stimuli`: 1 for the first study; allow >1 later
- `temperature`, `model_id`, `max_tokens`
- `committed_minority`: optional `{agent_ids, fixed_label, start_round}`
- `topology_params`: community size, rewiring probability, hub id

`memory_mode=none` is the isolated baseline. Agents still act, but prompts contain no past interactions.

### 2. Agent

Each agent has:

- `agent_id`
- `model_id`
- a private ring buffer, capacity `H`, of own interactions only
- no pointer to other agents' buffers
- no shared memory object

Buffer record, written only for the two participants of a completed dyad:

```json
{
  "round": 17,
  "stimulus_id": "s0",
  "self_label": "Zevu",
  "partner_label": "Mokar",
  "partner_id": "a07"
}
```

Do not store a narrative summary generated by the model unless it is built solely from this buffer and is itself logged. Prefer raw records over model-written summaries. Summaries can smuggle interpretations such as "we failed to agree."

Partner id may be stored for analysis. It should not be shown to the agent unless a treatment explicitly studies reputation. Default prompt uses "the other participant," not a persistent name, to avoid relationship confounds in Study 1.

### 3. Game master / scheduler

The scheduler is the only component that sees the full population. It must not serialize that view into prompts.

Per round:

1. Sample dyads according to topology. In `random_dyad`, sample without replacement within the round if N is even.
2. For each dyad, build two prompts independently from each agent's private buffer.
3. Collect both label choices. If parsing fails, log the raw output and resample once. Do not show the partner's choice before both choices exist.
4. Reveal choices to the two participants only.
5. If rewarded, compute match locally. Do not announce a population winner.
6. Append one buffer record to each participant. Do not append it to anyone else.
7. Write an analyst log row that agents never read.

Forbidden scheduler behaviors:

- broadcasting the modal label
- injecting "most agents are choosing X"
- letting an agent read the scheduler's state
- carrying over a dyad transcript into a non-participant's next prompt
- using one shared conversation thread for the whole population

### 4. Analyst store

Separate database or parquet/CSV. Agents have no read access.

Interaction table, one row per participant per dyad (or one row per dyad plus a long participant field; prefer one row per directed participant so memory reconstruction is auditable):

- `run_id`, `seed`, `config_hash`
- `round`, `dyad_id`, `agent_id`, `partner_id`
- `stimulus_id`
- `choice`, `partner_choice`, `match` (analyst-only boolean)
- `prompt_sha256`, `raw_model_output`
- `memory_records_included` (list of round ids actually inserted)
- `label_order_shown`
- `reward_shown` (true/false)
- `feedback_text_shown` (exact string or null)

Population table, one row per round per stimulus:

- `entropy`
- `modal_label`, `modal_share`
- `n_unique_labels`
- `switch_rate`
- `largest_component_share` if using network exposure

## Prompt templates

Two templates only. Keep them short. Log them verbatim.

### No-reward template

```text
You are participant {agent_id}.
A situation is labeled {stimulus_id}.
Choose exactly one label from this list:
{shuffled_labels}

Reply with only the label.

Your own recent interactions, if any:
{own_buffer_or_none}
```

Own buffer rendering, if H>0:

```text
- Round {r}: you chose {self}; the other participant chose {partner}.
```

Do not add "therefore" or evaluative adjectives.

### Rewarded template

Add only this block, and only in the rewarded arm:

```text
Scoring rule for this pairing only:
If you and the other participant choose the same label, you receive {match_payoff} points.
If you choose different labels, you receive {mismatch_payoff} points.
Your objective is to maximize your own points across pairings.
You will be told the other participant's choice after both choices are submitted.
You will not be told other participants' choices.
```

After choices, rewarded feedback may be:

```text
Your choice: {self}
Other participant's choice: {partner}
Points this pairing: {points}
Your cumulative points: {total}
```

No-reward feedback is only:

```text
Your choice: {self}
Other participant's choice: {partner}
```

Never say success, failure, agreement, or consensus in either arm.

## Label protocol

- Generate nonce labels with a fixed syllable template, equal length, no English stems, no alphabet sequence.
- Example generator: CVCV from a consonant/vowel list, reject dictionary hits.
- Pool size fixed within a run.
- Reshuffle presentation order independently for every prompt, including the two members of a dyad, so order is not a shared signal.
- Run an isolated baseline (`memory_mode=none`, no partner) for at least 20 choices per agent or 20 sterile agents. Save P(label | no social exposure).
- If one label exceeds 0.25 under the isolated baseline, flag label bias. Either regenerate the pool or include baseline log-odds as a covariate. Do not silently proceed.

## Network treatments

Implement as adjacency constraints on who may be paired. Do not describe the network to agents.

- `random_dyad`: each round, random perfect matching or random pairs with replacement across rounds.
- `star`: hub appears in every round with one leaf; leaves do not meet each other. Hub id is config-fixed.
- `community`: two or three blocks; within-block pairing probability 0.9, between-block 0.1, configurable.

The hub must not receive a special system prompt. If the hub converges the population only because it sees more interactions, that is centralization, not decentralized emergence. The analyst can detect this; the prompt must not create it.

## Experimental matrices

### Study A — rewarded naming game

Fix `reward_mode=local_match`, `feedback_mode=numeric_score`, `memory_mode=own_interactions_only`.

Cross:

- topology: random, star, community
- H: 1, 5, 10
- seeds: at least 30 per cell for the primary random-dyad cell; 10 per cell elsewhere if budget-constrained
- optional minority treatment after round 50: 5 percent and 15 percent of agents locked to a non-modal label

Primary contrast is not "did they score points." Primary contrast is population entropy and modal share versus:

- isolated baseline
- star versus random
- fragmentation: two labels each above 0.3 after the last quintile of rounds

### Study B — no task-contingent reward

Full factorial:

- `reward_mode`: none vs local_match
- `memory_mode`: none vs own_interactions_only
- topology fixed to random_dyad in the core 2x2
- H fixed to 5 when memory is on; H ignored when memory is none
- seeds: at least 30 per cell

`feedback_mode` must be `choices_only` whenever `reward_mode=none`.
A contaminated cell that shows "you matched" without points is not the no-reward arm. Put it in a separate robustness factor if desired.

## Measurement outputs the simulator must compute

Do not ask the LLM to judge whether emergence occurred.

Per run, per stimulus, write:

- time series of Shannon entropy of choice shares
- modal share
- number of distinct labels used in the last 20 percent of rounds
- mean individual switch rate
- path-dependence table across seeds: identity of modal label, final modal share
- regression-ready exposure variables:
  - `personal_exposure`: times this agent previously saw the focal label as either own or partner choice
  - `local_partner_prevalence`: share of this agent's last H partners who used the focal label
  - do not put global prevalence into the agent prompt; the analyst may compute it

Emergence is not a column the simulator sets to true. The analyst decides after tests:

1. Entropy decline relative to the memory-none baseline.
2. Modal label differs across seeds more than label-prior predicts.
3. Exposure coefficients predict next choice beyond the isolated baseline.
4. In Study A, global consensus is not entailed by local match success: report the rate of stable multi-convention fragmentation.
5. Leakage audit passed.

## Acceptance tests

Ship these as automated tests before experimental runs.

1. Memory isolation: after a round, agent A's buffer length increases only if A was in the dyad. Agent C's buffer is unchanged.
2. Prompt audit: rendered prompt for C contains no utterance from a dyad C did not join.
3. No global stats: prompt text matches a denylist and does not contain counts such as "12 agents" or percentages of labels.
4. Reward switch: with `reward_mode=none`, the strings "points", "score", "success", and "failure" do not appear in prompts or feedback.
5. Order randomization: two agents in one dyad do not always see labels in the same order across 100 draws.
6. Replay: same seed and config hash reproduce pairings and label orders. Model stochasticity may remain if temperature > 0; log it.
7. Parser: outputs with extra prose are stored raw and coded as invalid, not silently mapped to a preferred label.

## Implementation notes for Claude Code or Cursor

- Put protocol text in versioned templates, not in ad hoc f-strings scattered across files.
- One function, `build_agent_prompt(agent, config, round)`, is the only prompt constructor. Tests import it.
- One function, `commit_dyad(dyad, choices, config)`, is the only memory writer.
- Analyst logging is append-only and outside the agent object.
- Add a `dry_run` mode that executes pairing and prompt assembly without model calls, so leakage tests are cheap.
- Config validation must reject illegal combinations: `reward_mode=none` with `feedback_mode=numeric_score`.
- Do not add a shared vector store. If a later study needs a public artifact, it must be a separate treatment flag defaulting to off, and it must not be built for these two studies.

## Out of scope for these two studies

- Shared whiteboard, institutional sanctions, role titles, or natural-language norm statements.
- Asking agents to explain whether a convention has emerged.
- Population-level reward for consensus.
- Letting agents choose any free-form English word. Free generation confounds pretrained lexical preferences with interaction-driven convergence. Nonce choice sets are required for the first experiments.
